# Feature Requests and Verification Status

Last reviewed: 2026-09-07. Status is based on the live `baconbot` SSH beta-test sessions and recent field validation notes. Detailed UX findings are in `BBS-BETA-TEST-REPORT-2026-09-07.md`.

## Active: User Experience and Defects

- [x] Fix `!CB`: it currently redraws the main menu instead of checking bulletins or opening the Bulletin Menu. (v0.1.601)
- [ ] Fix the Node View hint `!V=all`: `!V` opens the selector but does not reset the view to All nodes.
- [x] Make interactive-fiction output flush promptly after restore and after commands. Delayed output can make Zork I/Zork II appear unresponsive. (v0.1.604: an immediate "Loading your saved game..." acknowledgement now goes out before the restore handshake, per the report's own suggested remedy)
- [x] Add an explicit back/cancel option to the mail message-number prompt. `0` currently says "Invalid message number." (v0.1.601)
- [x] Make post-send navigation explicit. After mail `END`, one `0` gives an unexplained acknowledgement and a second returns to main. (v0.1.601: mail now returns to the Mail Menu automatically after a send)
- [ ] Standardize every composer: advertise `!cancel`, confirm cancellation, and return to the immediate parent menu.
- [ ] Clarify channel creation's URL/PSK field with a format example, purpose, and optional/required status.
- [x] Improve profile bio validation: reject or explicitly warn on truncation and add a documented clear-bio action. (v0.1.604)
- [x] Clarify `!R` eligibility: it works after the latest mail is opened and kept, but that prerequisite is undisclosed. (v0.1.603: `!R` now falls back to the newest ordinary mailbox message, so that prerequisite no longer exists)
- [x] Make bulletin lists use contiguous selection numbers or label sparse values as record IDs. (v0.1.604)
- [ ] Add a `[0] Back` prompt to individual scoreboards and channel details reached through `!CHL`.
- [ ] Clarify Public Chatter filtering: no selected channels means all channels, while selected channels make an exclusive filter.
- [ ] Improve linked-device listings with user-readable labels and last-used/created information so a device can be safely unlinked. (v0.1.604 added the linked-at date to both listings; user-readable labels, beyond the raw node id, are still open)
- [x] Explain node-statistics freshness and unknown hardware/role records. (v0.1.602: Stats now reports real hardware model/role and non-zero recent-activity counts over SSH and web admin instead of `Unknown`/all-zero)
- [ ] Ensure Project Nomad uses BBS terms such as "Bulletins" and "Channels," not "forums."
- [ ] Explain Planetfall's restored state or offer an explicit resume/new-game choice.

## Verified Delivered

- [x] Private mail: inbox, compose, reply, mailbox retention, relay directory, direct recipient validation, and sender-side delivery acknowledgement.
- [x] Bulletin Boards: board selection, read, post, read-back, and Urgent permission architecture.
- [x] Channel Directory: browse, create, read-back, threaded comments, and comment read-back.
- [x] User Profiles: short name, bio, activity stats, and linked-device menu.
- [x] Games: Trivia King and interactive fiction titles (Zork I-III, Hitchhiker's Guide, Deadline, Enchanter, Planetfall, Starcross) launch; Trivia scoring persists.
- [x] Public Chatter: duration selection, pagination, filtering, and time selector.
- [x] MeshCore interface: companion serial/TCP/BLE configuration, contact inventory, encrypted direct-message mapping, broadcast-channel mapping, receive event conversion, and automatic 160-byte frame enforcement/chunking.
- [x] MeshCore serial companion hardware: Burlington runs it as its live secondary radio alongside Meshtastic; it is separately identified in diagnostics and uses its own peer/sync configuration.
- [x] MeshCore public chatter: captured real traffic is normalized; sender prefixes are conservatively parsed when present; direct-message identity wins when supplied by the protocol; path length is shown as hop count; and MeshCore channel names remain distinct from Meshtastic channels with the same index.
- [x] MeshCore-aware accounts and ACLs: MeshCore identities can link to an account without colliding with Meshtastic numeric IDs, and account permissions apply to linked MeshCore siblings.
- [x] MeshCore Web Admin and status support: companion-radio configuration, per-radio diagnostics/status, MeshCore protocol identity, advertised device role, and MeshCore-specific channel names are represented in the UI.
- [x] Dual-radio bridge software behavior: independent per-radio sync links share the local database, enforce each transport's frame limit, and isolate a failed radio link from the other interface.
- [x] SSH account behavior: shared-gate and direct registration/login flows, a stable per-account sender number, cross-session Zork-save restoration, one-session-per-account protection, and unsolicited late-reply delivery are live-verified.
- [x] SSH access control: self-registered SSH identities cannot post to Urgent, access web admin or fleet authority, or impersonate a radio/MQTT identity; an account must link an allowed real device to gain Urgent permission.
- [x] Fleet updates: signed target verification, per-node enrollment status, healthy state reporting, companion-service restart, and the deployed `bacon-ssh` restart path.
- [x] Encrypted invite export/import: broker connection details, certificates, and optional fleet public keys are packaged without secrets in clear text; the live `mqtt.nerdtunnel.net` bundle was verified.
- [x] Cross-node timestamp normalization: zork saves, game scores, channels, bulletins, and mail use normalized timestamps for sync hashing and ordering; live owned-node drift reduced to the intentionally churning public-chatter scope.
- [x] Synced deletion infrastructure: tombstone-aware delete functions and Web Admin score/profile deletion preserve cross-node deletes instead of letting reconciliation restore records.
- [x] Welcome and naming: configurable BBS greeting/name replication and node-name grouping are deployed; SSH Node View was verified against distinct Chattanooga and local content scopes.
- [x] Utilities: Fortune and Wall of Shame.
- [x] Project Nomad: live answer, follow-up question, and return-to-main-menu path.
- [x] Five-phase distributed sync: prioritized mail/bulletins/channels/profiles/game saves, SYNCSTATE/HASHMISS reconciliation, tombstones, and capability negotiation.
- [x] MQTT bridge: real broker operation and live node-to-node sync with RF disconnected; concurrent radio and MQTT links supported.
- [x] SSH access: account registration/login, mail relay path, session/rate protections, and Web Admin configuration.
- [x] API Gateway: allow-listed HTTP/AI relay, store-and-forward mailbox, and rate limiting.
- [x] Web Admin: dashboard, account controls, radio configuration, sync controls, database maintenance, and remote update tooling.
