# Feature Requests and Verification Status

Last reviewed: 2026-09-07. Status is based on the live `baconbot` SSH beta-test sessions and recent field validation notes. Detailed UX findings are in `BBS-BETA-TEST-REPORT-2026-09-07.md`.

## Active: User Experience and Defects

- [x] Fix `!CB`: it currently redraws the main menu instead of checking bulletins or opening the Bulletin Menu. (v0.1.601)
- [x] Fix the Node View hint `!V=all`: `!V` opens the selector but does not reset the view to All nodes. (v0.1.607: rather than make !V uniquely act instead of navigate -- inconsistent with every other bang shortcut -- the hint now reads "!V to change", describing what it actually does)
- [x] Make interactive-fiction output flush promptly after restore and after commands. Delayed output can make Zork I/Zork II appear unresponsive. (v0.1.604: an immediate "Loading your saved game..." acknowledgement now goes out before the restore handshake, per the report's own suggested remedy)
- [x] Add an explicit back/cancel option to the mail message-number prompt. `0` currently says "Invalid message number." (v0.1.601)
- [x] Make post-send navigation explicit. After mail `END`, one `0` gives an unexplained acknowledgement and a second returns to main. (v0.1.601: mail now returns to the Mail Menu automatically after a send)
- [x] Standardize every composer: advertise `!cancel`, confirm cancellation, and return to the immediate parent menu. (the four named instances -- channel creation, channel comments, device unlink, Project Nomad questions -- are all fixed: the first three shipped earlier this session, Project Nomad in v0.1.607, which also registers it so the bang form of cancel reaches the handler instead of being submitted as the question)
- [x] Clarify channel creation's URL/PSK field with a format example, purpose, and optional/required status. (v0.1.607: the prompt now gives a Meshtastic URL / MeshCore PSK example and says the field isn't required)
- [x] Improve profile bio validation: reject or explicitly warn on truncation and add a documented clear-bio action. (v0.1.604)
- [x] Clarify `!R` eligibility: it works after the latest mail is opened and kept, but that prerequisite is undisclosed. (v0.1.603: `!R` now falls back to the newest ordinary mailbox message, so that prerequisite no longer exists)
- [x] Make bulletin lists use contiguous selection numbers or label sparse values as record IDs. (v0.1.604)
- [x] Add a `[0] Back` prompt to individual scoreboards and channel details reached through `!CHL`. (v0.1.607)
- [x] Clarify Public Chatter filtering: no selected channels means all channels, while selected channels make an exclusive filter. (v0.1.607: the filter screen's own "(* = shown)" legend now stars every channel when nothing is chosen, since that's genuinely what's being shown -- no extra bytes spent on new text)
- [ ] Improve linked-device listings with user-readable labels and last-used/created information so a device can be safely unlinked. (v0.1.604 added the linked-at date to both listings; user-readable labels, beyond the raw node id, are still open)
- [x] Explain node-statistics freshness and unknown hardware/role records. (v0.1.602: Stats now reports real hardware model/role and non-zero recent-activity counts over SSH and web admin instead of `Unknown`/all-zero)
- [ ] Ensure Project Nomad uses BBS terms such as "Bulletins" and "Channels," not "forums."
- [x] Explain Planetfall's restored state or offer an explicit resume/new-game choice. (v0.1.606: traced live -- not a real restored/leaked save at all, ruled out via a byte-identical story file and a fresh-account repro. It was the installed dfrotz build producing a non-deterministic garbage Moves figure on Planetfall's own opening status line specifically. Fixed by zeroing Score/Moves on a freshly spawned session before any restore check runs.)

## Active: Product and Operations

- [x] Publish a simple indented text map of system menu paths, stopping at each game launch item. (docs/MENU-MAP.txt)
- [x] Add configurable first-connection welcome content: BBS public name, affiliated-node names, and Web Admin editing. (Already delivered -- Settings > Welcome & Identity: public name, greeting, this node's own line, the affiliated-node list toggle, a cross-node identity-trust list, and a live per-transport preview at each byte budget. Was never checked off here.)
- [x] Add Web Admin dependency-install support per operating system. (v0.1.613: Settings > Dependencies -- OS-detected, read-only. Deliberately diagnostic rather than an installer: an admin-password-gated web button that shells out to apt/brew with root privilege would be a second, unsigned way to run code on this node, exactly what Fleet's signed instructions exist to be the only way to do. Shows what's missing and the same command README.md already documents for it.)
- [ ] Improve connected-device inventory collection and display actual hardware/role information.
- [ ] Add more themes.
- [ ] Investigate the single-node status icon behavior.
- [x] Ensure games fail gracefully when the interpreter is unavailable. (v0.1.610: start_zork_session()/resume_zork_session() already returned a real, informative error on every failure -- no interpreter installed, story file missing, the interpreter process failing to spawn, a live session found dead on resume -- but _launch_game() showed it and then unconditionally piled a false "Zork I started/resumed/restored. Send X to exit." on top, and parked the session in ZORK state regardless. It now checks has_zork_session() again right after the call as ground truth and, on a genuine failure, shows only the real error and returns to the Games menu instead.)
- [x] Review game text truncation/terminal formatting. (v0.1.611: send_zork_command already scaled its per-turn output to the caller's transport via response_limit_for(), but the very first message a player ever saw from a game -- the opening intro, or the restore/look text for a saved game -- fell back to the flat 900-char radio ceiling regardless, since start_zork_session() had no way to receive the wider SSH-scaled limit at all. A long opening scene, Planetfall's especially, was truncated over SSH -- 8192 bytes per message there -- for no reason ordinary play already avoided. start_zork_session() now takes the same max_chars every other call in this path already respects.)
- [x] Review global quick keys so game input cannot accidentally navigate to BBS settings. (v0.1.609: Zork already had this -- an unconditional early return before the bang-prefix router. Trivia King didn't: bare letters were safe (it never populates the `handlers` dict a MENU/MAIN_MENU state's single-letter lookup uses), but a bang-prefixed Quick Command like !CM was still intercepted as the global command mid-game instead of reaching the game as input. Both games now get the same early, unconditional claim on their input.)
- [ ] Consider combining Linux services where that improves deployment and failure isolation.
- [ ] Restructure modules where it reduces complexity without disrupting the running system.
- [ ] Extend MeshCore support with user account rooms and relayed room text.
