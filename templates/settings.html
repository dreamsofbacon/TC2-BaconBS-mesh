Links & Services

Everything this node is connected to. Links carry BBS traffic (radios, MQTT bridges) and can be reconnected individually — the connection is dropped and re-established (with retry backoff) while the BBS, the sync engine, and every other link keep running. Use that after changing a broker's settings, or when one link is stuck but the rest are fine; it is not a service restart and nothing is lost. Services (JS8Call, API gateway) are shown for visibility only — they carry no sync traffic and have no separate connection to cycle.

Transmission Pacing

Raise speed for debugging, or slow it down if you need cleaner over-the-air pacing. Environment variables still override GUI settings while they are present.

Turbo uses the smallest normal delays and is useful when you want sync traffic to move as fast as possible.

⚠ Warning: Only enable turbo on small meshes (typically 2–3 BBS nodes on the same channel). The inter-frame pause is what prevents LoRa packet collisions on busy meshes; with 3+ active BBS peers turbo can worsen convergence by causing the very packet loss it tries to outrun.

Delay after normal sync frames such as bulletins, mail, and channels.

Resolve Save by Best Candidate

Ask every configured peer for a specific Zork save candidate, then choose the best result by newest timestamp, then larger payload size, then stable hash tie-break.

Force Full Resync to Peer

Use this when a peer node was wiped and rebuilt and its game data or other content is not converging via normal hash repair. This clears the in-memory sync cache for that peer and triggers a complete database push to it.

API Gateway / Project Nomad

When enabled, this internet-connected node fulfills API requests from offline mesh peers — a generic HTTP GET to an allowed host, or an AI prompt relayed to a locally-hosted Project Nomad (Ollama / OpenAI-compatible) endpoint. By default any node in the general allow-list may use the gateway; set an "Allowed requester nodes" list below to lock it down to specific nodes. Add A to the Utilities menu items to expose it to users.

Access control

Lock the gateway down to these node IDs only. Leave blank to allow any node in the general allow-list (the current open behaviour). When set, this list overrides the general allow-list for gateway access — only these nodes may issue API/AI requests.

Project Nomad AI

Ollama default port is 11434. For an OpenAI-compatible server, use its host (the /v1 path is added automatically).

Sent as Authorization: Bearer <key> for the Project N.O.M.A.D and OpenAI-compatible dialects. A plain Ollama server usually needs none, but a N.O.M.A.D / Open WebUI front end normally rejects unauthenticated requests with a 403.

Ask for brevity, but don't tell a small model to drop conversational openers (“No preamble”, “answer only”). A 3B model takes it literally and stops replying to a greeting, completing it instead — “Hello” comes back as Hello, World! in C…. Factual questions still work, so it reads like dropped radio replies rather than a prompt problem.

Danger Zone

Wipe all local bulletin, mail, channel, profile, score, save, diagnostics, peer-state, and tombstone data from the SQLite database.

Type WIPE DATABASE exactly to confirm. If peer sync remains enabled, remote nodes may repopulate data on later sync cycles.

Subscriber Nodes (cache clients)

Node IDs of pull-only clients — e.g. a low-power Pico cache node. This gateway will answer their sync requests (WANT / HASHMISS) but will not push-sync or hash-repair to them, so they never cause reconcile churn. Put cache nodes here, not in the BBS sync-peers list. One node ID per line (or comma-separated).

Account Linking

Tunables for the self-service multi-device account system (Profile > Linked Devices in the mesh menu). See the Accounts page to view or manage individual accounts. Changes here take effect immediately, no restart needed.

Keep this low -- it's the main defense against brute-forcing a 6-digit code.

Used by Linked Devices > [6] Request code, delayed. A dual-boot device can't receive anything while it reboots into its other protocol, so the code is held this long, then sent to every device already linked to the account. The code's lifetime is extended by the same amount, so the time available to redeem it is unchanged.

Storage / Database Size Cap

Keep the database under a size limit on long-running unattended nodes. When the on-disk database (including the WAL) exceeds the cap, the oldest content is deleted to bring it back under — bulletins, channel comments, and mail. These deletions propagate over the mesh like any other delete, so every node (including a Pico cache node) prunes the same records the same way. 0 disables the cap (keep everything — the default).
